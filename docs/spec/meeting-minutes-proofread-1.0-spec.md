# 會議記錄校稿（meeting-minutes-proofread）1.0 規格（公開版）：meeting-minutes-pro 的附屬工具

> **公開版**：本檔是會議記錄校稿 **1.0.0** 規格的公開版，適用 1.0.x。會議記錄校稿是 meeting-minutes-pro（下稱 Pro）的**附屬工具**：
> 有自己的原始碼目錄、安裝包、版號與 Release，安裝到已安裝的 Pro runtime。
> 依據：Pro 2.2.0 的程式（下稱「Pro 2.2.0」）與 Pro 規格公開版 [`meeting-minutes-pro-2.2-spec.md`](meeting-minutes-pro-2.2-spec.md)（標記格式、全文用字統一）、
> [`meeting-minutes-pro-2.1-spec.md`](meeting-minutes-pro-2.1-spec.md)（網頁版版型與播放器）。Pro 這一側的配合見 [`meeting-minutes-pro-2.3-spec.md`](meeting-minutes-pro-2.3-spec.md)。
> **章節號與開發用的原規格相同**：程式註解寫的「規格 §x.y」就是本檔的同一節。原規格裡屬於開發流程的段落（§13 工作拆分）在公開版省略，但保留章節號。
> 公開 repo 的路徑：工具在 `proofread/meeting-minutes-proofread-v1.0.0/`、測試在 `proofread/tests/`、打包工具在 `proofread/tools/`。
> 撰寫規格時另做了一套示範用的**試作程式**與合成素材（不公開，附錄 A）；試作與本檔不一致時以本檔為準。
> 標示：**〔規格確認〕**＝撰寫規格時以試作程式與合成素材實測的結果（附錄 A）；**〔推論〕**＝未直接驗證（附依據）；**〔規格決定〕**＝本規格自行決定的細節（附理由）。
> 「`$MMH`」＝`MEETING_MINUTES_PRO_HOME`（Windows 預設 `%LOCALAPPDATA%\meeting-minutes-pro`、macOS `~/Library/Application Support/meeting-minutes-pro`）；
> 「輸出資料夾」＝`<檔名>_minutes/`；「校正版」＝`transcript.corrected.md`；「稿」＝一個輸出資料夾裡要校的逐字稿。

## 0. 摘要

### 0.1 1.0.0 做什麼

| 功能 | 一句話 | 章節 |
|---|---|---|
| 本機網頁應用程式 | 用 Pro 已裝好的 Python（只用標準函式庫，不多裝套件）在 127.0.0.1 開一個小服務，預設瀏覽器開啟；不做桌面 App、不做純靜態 HTML | §3、§4 |

| 多份同時 | 同一位使用者只有一個服務；每份稿一個分頁；首頁列開著的稿與最近的稿；同一份再開一次帶到已開的分頁；存檔帶版本號，兩處同改時後存的被擋下 | §3.4～§3.8、§6.3 |

| 任意處可改 | 選取標記以外的任何文字直接改，改過的地方成為「人工修改」標記，可再改或刪除 | §5.5 |
| 狀態與進度 | 每處有未處理／已確認／已改／已退回四種狀態（形狀＋圖示＋顏色），全篇進度條，「只看未處理」 | §5.4、§9 |
| 暫存與接續 | 整篇自動暫存在輸出資料夾的 `.proofread/`，關掉再開接著校；Pro 重跑校正覆蓋校正版時偵測並提供帶入 | §6 |
| 定稿 | 產出 `transcript.final.md`（定稿逐字稿）與 `transcript.final.srt`（定稿字幕，沿用 Pro 的字幕對時）；名詞寫法同步到會議記錄／筆記（先備份、網頁版一起重產）；可選按鈕「用定稿重做會議記錄」（呼叫模型、要花費、按了才做，重產網頁版） | §7 |
| 經驗匯入 | 從校稿結果整理「原文 → 正確寫法」（詞與片語）與新名詞，列建議、勾選後匯入 `corrections.tsv` 與 `glossary.txt`；符合 Pro 固定錯誤條件的預設勾選；匯入前備份、可復原 | §8 |
| 寫入動作看得到 | 頂端固定的存檔狀態列（已儲存／儲存中／有未儲存的變更／儲存失敗＋原因＋重試）、「儲存」按鈕與 Ctrl＋S（⌘S）、有未儲存的變更時離開會提示、服務結束前先存；定稿、匯入、名詞同步、重做都先出**確認畫面**（要寫哪些檔、幾筆、先備份到哪裡、費用估算）再出**結果畫面**（實際寫入的檔名、筆數、備份檔名、「開啟資料夾」、失敗原因）；接續時顯示「上次儲存、已處理 N／M 處」；稿內操作紀錄 | §6.4、§6.6、§6.8、§7.6、§9.10 |
| 獨立發行 | 獨立安裝包、獨立版號 1.0.0、Release `proofread-v<版號>`（`--latest=false`）；版本相容表；Portal 首頁、安裝、功能、使用方法、設計理念五處頁面與 `mm-release.json` 欄位 | §2、§11 |

### 0.2 不做什麼（§14 後續候選）

- 不編輯會議記錄／筆記的本文（只同步名詞寫法）；不改講者對應（`S#` 與姓名）。
- 不做多人同時校稿、雲端同步、桌面 App 打包。
- 手機寬度只能檢視，不能校稿（§9.6）。
- 不提供 Claude App 上傳版（沙盒沒有本機服務，§3.10）。
- 不改 `transcript.md`、`transcript.corrected.md`、`transcript.srt`、`transcript.cues.srt`、`transcript.corrected.srt`（只新增定稿檔）。

## 2. 安裝與相容

### 2.1 安裝包內容

`meeting-minutes-proofread-v<版號>-installer.zip`（唯一的 Release 附件）解開後：`install.cmd`（Windows 雙擊）、`install.command`（macOS 雙擊）、
`install.ps1`、`install.sh`、`uninstall.cmd`、`uninstall.command`、`README.md`、`LICENSE`、`payload/app/**`。
**不含任何第三方套件**：伺服器、前端都只用 Python 標準函式庫與瀏覽器內建功能（前端不用框架、不載入 CDN）。所以不需要 `pip install`、不碰 Pro 的 venv 套件。

### 2.2 偵測 Pro

安裝程式與每次服務啟動都做（`mmproof_pro.check()`）：

1. `$MMH`：環境變數 `MEETING_MINUTES_PRO_HOME`，沒有就用 Pro `common.data_home()` 的預設位置（同 Pro 2.2.0 `common.py`）。
2. 必須都存在：`$MMH/config.json`、`$MMH/scripts/common.py`、Pro 的 Python（Windows `$MMH/venv/Scripts/pythonw.exe` 與 `python.exe`；macOS `$MMH/venv/bin/python`）。
3. 版號：`$MMH/scripts/common.py` 的 `VERSION`（讀不到時用 `config.json` 的 `runtime_version`）≥ 最低版本（§2.4）。
4. **介面檢查**（相容性的真正依據）：用 Pro 的 Python import `$MMH/scripts` 的模組，確認下列名稱都在，且 `consistency.MARK_RE.pattern` 與工具內建的標記樣式**逐字相同**：
   `common.{VERSION, data_home, load_config, setting, default_glossary, corrections_path}`、
   `consistency.{MARK_RE, key_of, COMMON_WORDS}`、`corrections.{load, backup, append_rows, HEADER, MIN_LEN}`、
   `subtitles.{map_corrected, recue, render_srt, options}`、`render_html.render`。
   import 時設 `PYTHONDONTWRITEBYTECODE=1`（不在 Pro 的 `scripts/` 留 `__pycache__`）。

| 結果 | 安裝程式 | 服務啟動時 |
|---|---|---|
| 沒裝 Pro（1、2 不成立） | 停止：「請先安裝 meeting-minutes-pro 2.2.0 以上」＋Portal 安裝頁網址；exit 2 | 啟動器跳對話框同一句話，不啟動 |
| 版號低於最低版本 | 停止：「meeting-minutes-pro 版本 X 太舊，請先升級到 2.2.0 以上」；exit 2 | 同左 |

| 通過 | 繼續 | 繼續；`version.json` 的 `pro_version_at_install` 與目前不同時只記 log |

### 2.3 安裝步驟

**Windows（`install.ps1`，不需要系統管理員）**：

1. 偵測 Pro（§2.2）。
2. 有執行中的舊版服務（`state/instance.json` 連得上）→ 用交接密鑰送 `{"shutdown": true}`（§3.4），等它結束（最多 10 秒）。
3. 刪掉 `$MMH/proofread/app/` 後整個複製新的；寫 `version.json`；`state/` 保留。
4. 右鍵「傳送到」：`[Environment]::GetFolderPath("SendTo")\會議記錄校稿.lnk`，
   `TargetPath = $MMH\venv\Scripts\pythonw.exe`、`Arguments = -B "$MMH\proofread\app\mmproof_launcher.py"`、`WorkingDirectory = $MMH`、
   `IconLocation = %SystemRoot%\System32\imageres.dll,<編輯圖示>`（同 Pro 用系統內建圖示的做法）。
5. 副檔名 `.mmproof` 關聯（HKCU，不需要管理員）：
   `HKCU\Software\Classes\.mmproof` (預設) = `MeetingMinutes.Proofread`；
   `HKCU\Software\Classes\MeetingMinutes.Proofread\shell\open\command` (預設) = `"$MMH\venv\Scripts\pythonw.exe" -B "$MMH\proofread\app\mmproof_launcher.py" "%1"`；
   `…\DefaultIcon` 同上圖示；完成後呼叫 `SHChangeNotify`（PowerShell 以 `Add-Type` 呼叫，或略過：重新登入後生效）。
6. 結束訊息：怎麼開（右鍵或雙擊）、Portal 使用說明網址。
7. 測試模式：同 Pro 的 `-TestRoot` 參數，把 SendTo、登錄機碼換到測試位置（登錄寫 `HKCU\Software\Classes\` 下的測試前綴鍵），供自動測試。

**macOS（`install.sh`）**〔推論，實作時實測〕：

1. 偵測 Pro（同上；Python 用 `$MMH/venv/bin/python`）。2. 停舊服務、換 `app/`（同上）。
3. `osacompile` 建立 `~/Applications/會議記錄校稿.app`：
   `on open theItems` → 把每個項目的 POSIX 路徑組成參數，`do shell script quoted form of PY & " -B " & quoted form of LAUNCHER & " " & 參數 & " > /dev/null 2>&1 &"`（背景執行，**不開終端機**）；
   `on run` → `display dialog "把會議的輸出資料夾（<檔名>_minutes）拖到這個圖示上，就會開始校稿。"`。
4. 在 `.app` 的 `Info.plist` 加 `CFBundleDocumentTypes`（副檔名 `mmproof`、`LSHandlerRank = Owner`）與 `UTExportedTypeDeclarations`，執行
   `lsregister -f`，讓雙擊 `.mmproof` 用這個 `.app` 開啟。關聯失敗時退回「把資料夾拖到 `.app` 上」（沿用 macOS 拖放入口）。

## 3. 一鍵開啟與服務生命週期

### 3.1 入口

| 入口 | 平台 | 怎麼做 | 傳給啟動器的 |
|---|---|---|---|
| 右鍵「傳送到 → 會議記錄校稿」 | Windows | 選一或多個輸出資料夾（或媒體檔、資料夾裡的檔）→ 右鍵 → 傳送到 | 所有選取的路徑（同一個行程收到全部；Windows 命令列上限約 32,000 字元，超過時 Explorer 會分批，各批都交給同一個服務，結果相同） |
| 雙擊 `會議記錄校稿.mmproof` | Windows／macOS | 第一次用任何入口開啟某份稿時，啟動器在該輸出資料夾寫這個小檔（內容一行 `meeting-minutes-proofread 1`，不含路徑）；之後雙擊它就開 | 這個檔的路徑（啟動器換成所在資料夾） |
| 拖到「會議記錄校稿.app」 | macOS | 沿用 Pro 的拖放方式 | 所有拖入的路徑 |
| 首頁的「接續」 | 全部 | 服務已在執行時，從首頁開最近的稿 | 只傳最近清單裡的 id（§4.4） |

〔規格決定〕捷徑用自訂副檔名而不是 `.lnk`：`.lnk` 要寫死 Pro 的絕對路徑，資料夾搬到別的電腦或 Pro 重裝到別處就失效；`.mmproof` 不含路徑，靠副檔名關聯找到目前安裝的工具。

### 3.2 路徑換算（啟動器）

每個傳入的路徑依序試：① 本身是資料夾 → 它；② 是檔案 → 所在資料夾；③ 是檔案 → 同層的 `<主檔名>_minutes/`（使用者對錄音檔按右鍵的情況）。
第一個「含有 `transcript.corrected.md` 或 `transcript.md`」的就是輸出資料夾。都不成立 → 收集起來，最後用一個對話框列出「這些不是會議的輸出資料夾（裡面沒有 transcript.md）」。
同一次傳入的重複資料夾（解析後的實際路徑相同）只開一次。〔規格決定〕一次超過 10 份時只開首頁（10 份以上同時開分頁容易讓瀏覽器卡住），全部列在首頁的「開著的稿」。

### 3.3 背景啟動、不出命令列視窗

- **Windows**：入口（`.lnk`、`.mmproof` 關聯）直接執行 Pro venv 的 `pythonw.exe`（GUI 子系統，**沒有主控台視窗**）。啟動器需要啟動服務時，同樣用 `pythonw.exe`，
  `subprocess.Popen(..., creationflags=DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW, stdin/stdout/stderr=DEVNULL, close_fds=True)`，
  啟動器交接完就結束，服務獨立存活。錯誤用 `ctypes.windll.user32.MessageBoxW` 對話框告知（不印到不存在的主控台）。
- **macOS**：`.app` 用 `do shell script … &`（背景、輸出丟棄），不開「終端機」；服務用 `start_new_session=True` 脫離。錯誤用 `osascript -e 'display dialog …'`。
- 〔規格確認〕試作的入口是 `.cmd`，雙擊時會閃一下主控台（`.cmd` 的限制）；正式版入口不經 `.cmd`。實測啟動器結束後只剩 `pythonw.exe` 的服務行程（附錄 A.3）。

### 3.4 單一服務與交接

- 服務啟動時寫 `state/instance.json`：`{"pid", "port", "secret", "version", "started_at"}`（暫存檔＋`os.replace()`）。`secret` 是 32 位元組隨機值（`secrets.token_urlsafe(32)`），
  只用於「啟動器 → 服務」的交接；檔案在使用者自己的 `$MMH` 底下（Windows `%LOCALAPPDATA%`、macOS `~/Library/Application Support`，預設只有本人可讀）。
- 啟動器流程：
  1. 讀 `instance.json` → `POST http://127.0.0.1:<port>/api/handoff`（標頭 `X-MMP-Handoff: <secret>`、**不帶 Origin**，§4.3）送 `{"folders": [...]}`；成功就用回傳的網址開瀏覽器，結束。
  2. 連不上（服務已異常結束）→ 刪掉殘留的 `instance.json`，進第 3 步。
  3. 以 `os.open(start.lock, O_CREAT | O_EXCL)` 取得啟動鎖（拿不到 → 每 0.2 秒重讀 `instance.json` 嘗試交接，等另一個啟動器把服務帶起來；鎖檔超過 30 秒視為殘留並刪除）。
  4. 拿到鎖後再試一次交接（避免剛好有人啟動完成），還是不行就背景啟動服務，等 `instance.json` 出現並交接成功（上限 15 秒），最後刪鎖。
  5. 15 秒內沒成功 → 對話框「會議記錄校稿沒有啟動成功。請再試一次；還是不行請重新執行安裝程式。」
- 版號不同（`instance.json` 的 `version` ≠ 安裝的版號，升級後舊服務還在跑）→ 交接 `{"shutdown": true}`，等舊服務結束後依第 3 步啟動新版。
- 交接回應：每份稿 `{"input": <資料夾名>, "id": <12 碼>, "status": "open"|"attach"|"invalid", "url": <一次性登入網址>}`。啟動器只把 `url` 交給瀏覽器，不寫檔、不印出。
- 〔規格確認〕兩個啟動器同時啟動（沒有服務時）→ 只有一個服務，兩個都交接成功（附錄 A.2）。

### 3.5 連接埠

綁 `("127.0.0.1", 0)`：由作業系統挑一個空的臨時連接埠，**不會有被占用的問題**，也不需要重試邏輯。〔規格決定〕不用固定連接埠：固定連接埠可能被別的程式占用，
而且網址不會被使用者書籤化（登入要一次性權杖，§4.2），固定沒有好處。實際連接埠只寫在 `instance.json`。

### 3.6 分頁（每份稿一個）

- 每份稿的網址是 `/d/<id>`，`id` = `sha256(輸出資料夾實際路徑的小寫)` 的前 12 個十六進位字元（同一資料夾永遠同一個 id；不洩漏路徑）。
- 交接時：
  - 這份稿**沒有**分頁持有編輯權 → `status: "open"`，網址導到 `/d/<id>`。
  - **已有**分頁持有編輯權（§3.7）→ `status: "attach"`，網址導到 `/d/<id>?attach=1`：這個新分頁只顯示提示「這份稿已經在另一個分頁開啟（同一份稿只能在一個分頁修改）。
    請切換到瀏覽器分頁列上的『<名稱>｜會議記錄校稿』分頁；那個分頁的標題會閃爍提示」，按鈕「改在這個分頁編輯」（接手）與「只看」。
    同時服務把該稿標記 `attention`，原分頁下次心跳收到後標題閃爍 10 秒（「● 請看這裡｜…」）並顯示一行提示；新分頁也用 `BroadcastChannel('mmproof')` 通知原分頁立即閃爍。
  - 〔規格決定〕不嘗試「把原分頁拉到前面」：瀏覽器不允許網頁或本機程式把指定分頁切到前景（`window.focus()` 在非使用者操作時無效），所以改成「提示頁＋原分頁閃爍」，保證**不會出現第二個可編輯的分頁**。
- 首頁 `/`：列開著的稿與最近的稿（§9.7）。只能經由一次性登入網址進入（啟動器在沒有有效路徑、或一次超過 10 份時開首頁）。

### 3.7 編輯權（同一份稿只有一個分頁能改）

| 項目 | 值 |
|---|---|
| 取得 | 分頁載入後 `POST /api/doc/<id>/lease {"tab": <分頁隨機 id>}`；沒有人持有或已過期 → 給這個分頁 |
| 心跳 | 每 10 秒同一個請求（前景分頁）；回應帶 `attention`（§3.6）與目前 `rev` |
| 過期 | 150 秒沒有心跳。理由：瀏覽器把背景分頁的計時器節流到每分鐘一次（Chrome 的 intensive throttling），過期時間要大於 2 次節流間隔 |
| 放開 | 分頁 `pagehide` 時 `fetch(…/bye, {keepalive: true})` 立刻放開（關分頁、關瀏覽器、重新整理都會觸發） |
| 接手 | `{"takeover": true}`：不管目前持有者，直接改給這個分頁；原分頁下次心跳發現失去編輯權 → 變唯讀並顯示「這份稿已在另一個分頁編輯，這個分頁改成只能看（你在這裡的修改都已暫存）」與「改回在這個分頁編輯」 |
| 沒有編輯權時寫入 | 所有寫入 API（暫存、定稿、匯入、同步、重做）回 `423`，前端轉唯讀 |

### 3.8 自動結束

- 條件：沒有任何稿的編輯權還在有效期內、沒有執行中的背景工作（重做會議記錄），而且**最後一個 HTTP 請求**之後超過 `idle_seconds`。
- `idle_seconds` 預設 **180**（`$MMH/proofread/config.json` 的 `idle_seconds`，範圍 30～3600，不合法用預設）。首頁分頁每 15 秒送 `/api/ping`，所以首頁開著時服務不會結束。
- 結束時：關閉監聽、刪 `instance.json`（只在內容的 `pid` 是自己時刪，避免刪到新服務的檔）。
- **服務要結束而分頁還開著**（安裝程式升級或移除時送交接 `{"shutdown": true}`，§2.3、§3.4）：服務進入「關閉中」，持有編輯權的分頁在下一次心跳收到 `closing: true` →
  有未儲存的變更就立刻儲存（操作紀錄記「儲存（服務關閉）」）→ 放開編輯權 → 轉唯讀並跳對話框「正在升級或移除會議記錄校稿。你的修改已儲存（HH:MM:SS）。完成後從右鍵或捷徑重新開啟即可接續」。
  服務在所有編輯權都放開後結束，最多等 15 秒（超過就結束；分頁的修改仍在畫面上，重新開啟後可用「下載這個分頁的修改」或再存一次）。
  〔規格確認〕`--shutdown` 後分頁收到 closing、存檔成功、放開後 1.5 秒結束（附錄 A.2）。
- 〔規格確認〕全部分頁離開後在閒置設定值（測試 15 秒）＋約 1 秒內結束（附錄 A.2）。

### 3.9 異常結束後的殘留

| 殘留 | 處理 |
|---|---|
| `instance.json`（服務被強制結束、當機、關機） | 啟動器交接連不上 → 刪除並重新啟動（〔規格確認〕附錄 A.2） |
| `start.lock` | 超過 30 秒視為殘留，刪除後重試 |
| 輸出資料夾 `.proofread/` 裡的 `.~*.tmp`（寫到一半斷電） | 載入該稿時刪除超過 1 小時的 `.~*.tmp`；正式檔因為「暫存檔＋`os.replace()`」不會是半個檔 |
| 編輯權 | 只存在服務的記憶體，服務重啟後全部清空，不會卡住 |
| 背景重做會議記錄被中斷 | 由 Pro 自己處理（Pro 寫檔前先改名備份舊的 `.md`）；工具重啟後該工作狀態消失，畫面顯示「上次的重做沒有完成，請再按一次」（依 `meeting-minutes.md` 的時間比對 `session.json` 的 `redo.started_at`） |

### 3.10 Claude App 模式

Claude App 的沙盒沒有本機 runtime，不能開本機服務，**1.0.0 不提供**。Pro 的 SKILL.md 不變：在 Claude App 中，使用者照舊請 Claude 依 `transcript.corrected.md` 在對話中補校。
Portal 工具頁寫明「只能在安裝了 Pro 的電腦上使用」。

## 4. 安全

### 4.1 綁定與請求來源

- 只綁 `127.0.0.1`（IPv4 loopback）。不綁 `0.0.0.0`、不綁 `::1`、不綁區網位址。
- 〔規格確認〕127.0.0.1 連得上；本機其他 7 個位址（區網 IPv4／IPv6、`::1`）全部連不上；Windows 回報的監聽位址只有 `127.0.0.1`（附錄 A.2）。

### 4.2 一次性登入權杖與 cookie

| 項目 | 規則 |
|---|---|
| 登入網址 | `http://127.0.0.1:<port>/login?t=<權杖>&next=/d/<id>`（或 `next=/`）；只由交接 API 產生 |
| 權杖 | `secrets.token_urlsafe(24)`；**60 秒內有效、用一次就失效**；比對用 `hmac.compare_digest` |
| 換成 cookie | 驗證成功 → `Set-Cookie: mmp_s=<32 位元組隨機值>; HttpOnly; SameSite=Strict; Path=/`，`303` 轉到 `next`（`next` 只接受 `/` 或 `/d/<12 碼>`，可加 `?attach=1`；其他一律改成 `/`） |
| cookie 有效期 | 服務存活期間（記憶體）；服務結束即失效，下次一律經由入口重新登入 |
| 沒有 cookie | 頁面回 401「請從右鍵或捷徑開啟」；API 回 401／403 |

### 4.3 每個請求的檢查

1. **Host**（防 DNS rebinding）：只接受 `127.0.0.1:<port>` 與 `localhost:<port>`，其他一律 `403`。
2. **寫入類請求**（POST／PUT）：cookie 有效，而且 `Origin` 等於 `http://127.0.0.1:<port>`（或 `localhost`），而且有 `X-MMP: 1` 標頭；任一不符 `403`。
   自訂標頭讓跨站表單與簡單請求都無法偽造（需要 CORS 預檢，而服務不回任何 CORS 標頭）。
3. **交接 API**：`X-MMP-Handoff` 等於 `instance.json` 的密鑰，而且**沒有** `Origin` 標頭（瀏覽器發出的 POST 一定帶 Origin，所以網頁無法呼叫交接）；不需要 cookie。
4. 請求本文上限 20 MB（暫存檔最大的情況：3 小時稿約 1,000 處決定，實際 < 1 MB）；JSON 解析失敗 `400`。

〔規格確認〕錯的權杖 401；同一權杖第二次 401；錯的 Host（`evil.example`、`127.0.0.1.nip.io`）403；沒有 Origin、外站 Origin、缺 `X-MMP` 都 403；沒有 cookie 401；
交接 API 錯的密鑰、帶 Origin 都 403（附錄 A.2）。

### 4.4 只能存取被開啟的輸出資料夾

- API 只收 12 碼 id，**不收任何路徑參數**。id 只有兩個來源：交接（啟動器傳入，§3.4）、最近清單（服務自己寫的 `recent.json`）。
- 每份稿能讀寫的檔案是固定清單：`transcript.md`、`transcript.corrected.md`、`transcript.json`、`meeting-minutes.md`／`notes.md`（＋同名 `.html`）、`.proofread/**`、
  定稿檔與它們的 `.bak`、`會議記錄校稿.mmproof`；媒體檔由 §9.8 的規則在伺服器端找出（不接受前端指定）。另外只寫 `$MMH/corrections.tsv`、`$MMH/glossary.txt`、`$MMH/backups/`。
- 靜態檔只有 `app.html`、`app.js`、`app.css` 三個固定名稱。
- 最近清單回給瀏覽器時不含路徑（只有 id、資料夾名、時間、進度）。
- 「開啟資料夾」（§7.6）：`POST /api/doc/<id>/reveal {"target": "folder"|"mmh"|"backups"}`，只能開這三個由服務決定的位置（該稿的輸出資料夾、`$MMH`、`$MMH/backups`），
  用作業系統的檔案管理員開（Windows `os.startfile`、macOS `open`）；其他值 `404`。〔規格確認〕任意路徑被拒（附錄 A.2）。
- 〔規格確認〕`/api/doc/../../etc/passwd`、未開啟的 id、`/static/../mmproof_server.py`、`%2e%2e` 都 404（附錄 A.2）。

### 4.5 CSP、外部資源、其他標頭

每個回應都帶：

```
Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; media-src 'self';
  connect-src 'self'; font-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Cross-Origin-Resource-Policy: same-origin
Cache-Control: no-store
```

- 前端只有同源的 `app.js`、`app.css`；不載入字型、CDN、圖片、外部腳本；樣式只用 CSSOM（`style` 屬性被 CSP 擋）。
- 逐字稿內容一律用 `textContent` 放進頁面，不拼 HTML（防止逐字稿裡的 `<…>` 被當成標記）。
- 〔規格確認〕瀏覽器實測整個流程（主畫面、選單、經驗、定稿、首頁、提示頁、手機寬度）共 59 個請求，**非 127.0.0.1 的請求 0 個**，CSP 違規 0、頁面錯誤 0（附錄 A.4）。

### 4.6 防火牆不跳提示

- 依據：Windows Defender 防火牆的「允許存取」提示是在程式**接受來自網路的連線**（監聽非 loopback 介面）時出現；只綁 127.0.0.1 的程式收不到外部連線，不觸發提示〔推論，依 Windows 防火牆對 loopback 流量不套用規則的行為〕。
- 〔規格確認〕實測：啟動前後 `Get-NetFirewallRule` 總數 635 → 635、程式路徑含 python 的應用程式篩選 2 → 2（提示一旦出現，不論選允許或拒絕都會新增規則），畫面上沒有提示（附錄 A.3）。
- 檢查方式（實作時在 Windows 實機重做）：

  ```powershell
  $b = @(Get-NetFirewallRule).Count; $bp = @(Get-NetFirewallApplicationFilter | ? Program -match 'python').Count
  # 用右鍵「傳送到 → 會議記錄校稿」開一份稿，等瀏覽器開好
  $a = @(Get-NetFirewallRule).Count; $ap = @(Get-NetFirewallApplicationFilter | ? Program -match 'python').Count
  "$b → $a；python $bp → $ap"   # 兩組都要相同
  (Get-NetTCPConnection -LocalPort <port>).LocalAddress   # 只有 127.0.0.1
  ```
- macOS 應用程式防火牆：同樣只對接受外部連線的程式詢問〔推論〕；有 macOS 機器時開啟防火牆後實測。

### 4.7 紀錄與秘密

- `server.log` 只記「時間 方法 路徑 狀態碼」，不記查詢字串（權杖）、cookie、請求本文。
- 權杖、cookie、交接密鑰不寫進任何輸出資料夾、不出現在畫面上；啟動器不把網址印出（測試用的 `--no-browser` 只輸出不含網址的結果）。
- 執行「重做會議記錄」時以參數陣列呼叫 Pro（不經 shell，§7.5）。

## 5. 標記解析與資料模型

### 5.1 三種標記（以 Pro 2.2.0 為準）

標記樣式與 Pro 2.2.0 `auto_correct.MARK_RE`／`consistency.MARK_RE` **逐字相同**（介面檢查比對，§2.2）：

```python
MARK_RE = re.compile(r"\{([^{}→\n]*)→([^{}\n]*)\}|\[\?([^\[\]｜\n]*?)(?:｜([^\[\]\n]*))?\]")
```

| 種類（kind） | 語法 | 判定 | 畫面名稱 |
|---|---|---|---|
| `fix` | `{原文→修正}` | 原文、修正都非空，而且不屬於 `unify` | 校正 |
| `delete` | `{原文→}` | 修正為空 | 刪除 |
| `insert` | `{→補字}` | 原文為空 | 補字 |
| `unify` | `{原文→統一}` | 原文≠修正，而且 `consistency.key_of(原文) == key_of(修正)`（只差大小寫、空格、`.`、`-`） | 用字統一 |
| `uncertain` | `[?原文｜推測]` 或 `[?原文]` | 第 3 組有值 | 待確認 |
| `manual` | （畫面內部；存成 §5.5 的位置資料） | 使用者選取文字修改 | 人工修改 |

〔規格決定〕用字統一和校正的語法相同（Pro 2.2.0 設計如此，規格 2.2.0 §14），所以用 `key_of` 判斷：模型若剛好只改了大小寫（`kafka→Kafka`），也會顯示成「用字統一」，兩者對使用者的意義相同（寫法統一），不影響決定與定稿。

### 5.2 文件結構

- 來源：有 `transcript.corrected.md` 就用它；沒有（沒做 AI 校正）就用 `transcript.md`，此時沒有任何標記，只能做人工修改（§5.5），定稿照樣產生。
- 第一個單獨一行的 `---` 之前是表頭（標題、表頭說明、校正摘要、講者對應、待確認），之後是本文。沒有 `---` 時整份都是本文。
- 本文段落：`^\*\*\[(\d{1,2}:\d{2}:\d{2})\] ([^*\n]+?)\*\*：`（同 Pro `subtitles.HEAD`），時間補成 `HH:MM:SS`，講者原樣（`姓名（S#）` 或 `S#` 或 `S?`）。
- 段落被換行時，下一行（非空、不以 `>`、`#` 開頭）接回同一段（同 Pro `parse_md`）。
- 其他行（畫面行 `> 🖼…`、`> ⚠` 註記、空行）原樣保留在本文的相對位置，定稿時照樣輸出。
- 〈講者對應〉表讀成 `[(代號, 姓名, 依據)]`，定稿時原樣輸出。

### 5.3 識別碼

- 標記 id：`m<段落序>-<段內序>`（段落序從 0 起）。同一份來源（`sha256` 相同）每次解析得到相同 id，所以 `session.json` 可以用 id 存決定。
- 人工修改 id：`u` ＋時間戳＋隨機字元（前端產生，同一份稿內唯一）。
- 稿 id：§3.6。

### 5.4 狀態機

| 狀態 | 畫面 | 定稿文字 | 進度 |
|---|---|---|---|
| `pending` 未處理 | 黃框、`●`（待確認：橘色虛線框、`?`；用字統一：紫框） | 校正類用修正、待確認寫「原文〔?推測〕」（§7.3） | 未完成 |
| `accepted` 已確認 | 綠色底線、`✓` | 校正／統一／刪除／補字：修正；待確認：選的推測或原文 | 完成 |
| `edited` 已改 | 藍色底線、`✎` | 自由輸入的文字 | 完成 |
| `rejected` 已退回 | 灰色虛底線、`↺` | 原文（`delete` 退回＝保留原文；`insert` 退回＝不補） | 完成 |

| 動作（選單或鍵盤） | 校正、刪除、補字、統一 | 待確認 | 人工修改 |
|---|---|---|---|
| 選建議（`A`／選項 1） | → `accepted`（choice `suggest`） | 有推測：→ `accepted`（`guess`）；沒有推測：→ `accepted`（`orig`） | — |
| 選原文（`R`／選項 2） | → `rejected`（`orig`） | → `accepted`（`orig`：確認原文是對的） | — |
| 自由輸入（`E`／選項 3） | → `edited`（`free`，存輸入值） | → `edited`（`free`） | 改值（仍是 `edited`）；值改回原文＝刪除這個人工修改 |
| 改回未處理 | → `pending`（刪除決定） | → `pending` | 「刪除這個修改（回到原文）」 |
| 同樣的標記一起套用 | 同一種類、同原文、同建議、同推測、而且還是 `pending` 的其他標記一起套同一個決定（預設勾選；待確認預設不勾） | | |

- 全篇進度＝`(總標記數 − pending) / 總標記數`，總數含人工修改（人工修改一律算完成）。
- 決定存成 `{"choice": "suggest"|"orig"|"guess"|"free", "value"?: str}`；狀態由決定推出，不另存。

### 5.5 自由編輯成為新標記（人工修改）

- 使用者在**標記以外**的文字上用滑鼠（或鍵盤 Shift＋方向鍵）選取 → 出現「✎ 修改選取文字（E）」→ 輸入新文字 → 套用。
- 存成 `{"id", "para": 段落序, "start", "end", "orig": 選取的原文, "value": 新文字}`；`start`／`end` 是**段落原始字串**（校正版那一行的本文，含標記原樣）裡的字元位置。
- 規則（伺服器在每次暫存時檢查，任何一條不符 → `400`，前端顯示原因）：
  1. 範圍必須完全落在同一個「標記以外的文字片段」內（選取跨到標記 → 前端提示「選取範圍跨到標記了：請先處理標記，或分兩次選」）。
  2. `orig` 必須等於該位置的實際文字（防止稿件已變）。
  3. 同一段的人工修改不可互相重疊。
  4. `value` 不可含 `{`、`}`、`[?`、換行（標記符號）。
- 要在兩字之間補字：選取相鄰的一個字，改成「該字＋補字」。〔規格決定〕不支援空選取的插入，避免游標位置判斷錯誤。
- 標記內部的文字不直接改，改用該標記的選單（自由輸入）。
- **不變式**：人工修改相當於在原文上加一個 `{原文→新文字}` 標記，標記以外的文字仍與 `transcript.md` 逐字相同，所以定稿字幕可以用 Pro 的對時（§7.2）。

### 5.6 復原（undo）與重做（redo）

- 每個動作一筆歷史：`{"t": "d", "items": [{"id", "before", "after"}]}`（決定，一起套用的多處算一筆）、`{"t": "ma", "u"}`（新增人工修改）、`{"t": "me", "id", "before", "after"}`（改值）、`{"t": "md", "u"}`（刪除）。
- `Ctrl＋Z` 復原、`Ctrl＋Y`／`Ctrl＋Shift＋Z` 重做；做了新動作就清空重做堆疊。
- 歷史最後 200 筆存進 `session.json`（關掉再開仍可復原）；重做堆疊只在記憶體。

### 5.7 傳給前端的資料與效能

- `GET /api/doc/<id>/data` 一次回傳：解析後的段落（文字片段與標記）、`session`（決定、人工修改、歷史、rev）、`changed`（§6.5）、媒體名稱與種類、已有的檔案。
- 前端把整篇渲染成 DOM（段落用 `content-visibility: auto`），做決定只重畫受影響的段落。
- 〔規格確認〕3 小時合成長稿（900 段、1,050 處標記、約 7.9 萬字）：從開網址到全部段落出現 74 ms；每次「接受並跳到下一個」24 ms；自動暫存正常（附錄 A.5）。

## 6. 暫存與接續

### 6.1 位置〔規格決定〕

`<輸出資料夾>/.proofread/`：

| 檔案 | 內容 |
|---|---|
| `session.json` | 決定、人工修改、歷史、版本號、匯入紀錄、定稿紀錄（§6.2） |
| `source.md` | 開始校稿時的來源全文副本（校正版被 Pro 重跑覆蓋後，仍能顯示舊稿與帶入決定，§6.5） |
| `session.<時間>.bak.json`、`source.<時間>.bak.md` | 「用新版重新開始」前的備份 |

理由：需求是「整篇暫存在輸出資料夾」；放在資料夾裡，搬移、備份、換電腦都跟著走。用點開頭的資料夾名，在 macOS Finder 預設隱藏（Windows 會顯示，名稱清楚表示用途）。

### 6.2 `session.json` 格式

```json
{
 "format": "mm-proofread-session/1",
 "tool_version": "1.0.0",
 "rev": 7,
 "created_at": "2026-11-08T10:59:22+08:00",
 "saved_at": "2026-11-08T11:20:05+08:00",
 "source": {"file": "transcript.corrected.md", "sha256": "<64 碼>"},
 "marks": {"m0-0": {"choice": "suggest"}, "m6-0": {"choice": "guess"}, "m2-1": {"choice": "free", "value": "…"}},
 "manual": [{"id": "u…", "para": 1, "start": 34, "end": 36, "orig": "密等", "value": "冪等"}],
 "history": [ … 最後 200 筆 … ],
 "progress": {"pending": 0, "accepted": 13, "edited": 3, "rejected": 1, "total": 17, "manual": 3, "done": 17},
 "imports": [{"at": "…", "corrections": [["星荷", "星河"]], "glossary": ["NotebookLM"], "backups": {"corrections.tsv": "…"}, "after_corrections": "<sha256>"}],
 "finalized": {"at": "…", "rev": 7, "pending": 0},
 "redo": {"started_at": "…", "status": "ok"},
 "log": [{"at": "2026-11-08T11:20:05+08:00", "action": "定稿", "files": ["transcript.final.md", "transcript.final.srt"]}, … 最後 500 筆 …]
}
```

- 時間一律 ISO 8601 帶時區（伺服器取系統時間）。寫檔用暫存檔＋`os.replace()`，UTF-8、換行 `\n`。
- 格式升級：`format` 的主版號不同時，新版工具負責轉換並先備份成 `session.<時間>.bak.json`；遇到比自己新的主版號 → 唯讀開啟並提示升級工具。

### 6.3 版本號與衝突

- 每次暫存送 `base_rev`（分頁上次知道的版本號）；伺服器只在 `base_rev == 目前 rev` 時寫入，`rev + 1` 回傳新值。
- 不相等 → `409 {"error": "rev", "rev", "saved_at", "message"}`；前端轉唯讀並跳對話框「沒有存到：這份稿有更新的版本」，選項「載入最新版本」（重新載入）、「下載這個分頁的修改（JSON）」（不遺失）。
- 沒有編輯權 → `423`（§3.7）。編輯權保證同時間只有一個分頁寫；版本號再擋住「接手前送出、接手後才到」與「另一個分頁存過後，舊分頁拿回編輯權」的情況。
- 〔規格確認〕兩分頁同改一份：B 接手前只能看；B 接手後 A 存檔 423；B 依接手時的版本號存成功；A 拿回編輯權但版本號過期 → 409（附錄 A.2）。

### 6.4 存檔：自動暫存、手動儲存、狀態列、未存離開

**存檔狀態列**：在頂端列（固定在畫面上方，本文怎麼捲動都看得到，§9.1），一個有外框的區塊，內容與顏色：

| 狀態 | 顯示 | 顏色 | 何時 |
|---|---|---|---|
| 已儲存 | `✓ 已儲存 HH:MM:SS` | 綠 | 最後一次寫入成功，之後沒有修改 |
| 儲存中 | `儲存中…` | 藍 | 請求送出、還沒回應 |
| 有未儲存的變更 | `● 有未儲存的變更` | 黃、粗體 | 有修改，還沒送出（自動暫存倒數中） |
| 儲存失敗 | `✕ 儲存失敗（原因見下方）`，頂端列下方多一條整列寬的紅色提示：「儲存失敗：<原因>。修改還在這個分頁，沒有遺失；會每 5 秒自動重試。」＋「立刻重試」 | 紅 | 寫入失敗 |
| （其他）尚未修改／唯讀 | `尚未修改`／`唯讀（這個分頁不會儲存）` | 灰 | 新稿還沒動過／沒有編輯權或窄螢幕 |

- 失敗原因寫成使用者看得懂的話：連不上服務 →「連不上會議記錄校稿（服務可能已結束，請從右鍵重新開啟這份稿；修改還在這個分頁）」；寫檔錯誤 →「寫不進 .proofread/session.json（<錯誤類型>：<系統訊息>）」；其他 → `HTTP <碼>`。
  版本衝突與沒有編輯權不算「儲存失敗」，各有自己的對話框與橫幅（§6.3、§3.7）。
- **自動暫存**：每次決定或修改後 **1.2 秒**（之間再有修改就重新計時）送出整份決定（不是差異；3 小時稿 < 1 MB）。〔規格決定〕1.2 秒：連續按鍵校稿時不會每一鍵都寫檔，停手後很快就落地。
- **失敗重試**：每 5 秒自動重試，直到成功；成功後狀態回到「已儲存」，紅色提示消失。
- **手動儲存**：狀態列旁的「儲存」按鈕、`Ctrl＋S`（macOS `⌘S`，在輸入框裡也有效、會擋掉瀏覽器的「另存網頁」）。沒有變更時也寫一次（更新「已儲存」時間），
  按了一定有回饋：頂端浮出「已儲存 HH:MM:SS（已處理 n／N 處）」3.5 秒；失敗時浮出「儲存失敗：<原因>」。手動儲存記進操作紀錄（§6.8）。唯讀分頁按了顯示「這個分頁是唯讀，不會儲存」。
- **未存離開**：有未儲存的變更或正在儲存時，關分頁、關瀏覽器、重新整理 → `beforeunload` 讓瀏覽器跳出「確定要離開嗎？」；同時用 `fetch(…, {keepalive: true})` 送一次儲存（操作紀錄記「儲存（離開分頁）」）。
  〔規格確認〕瀏覽器實測：改一處後關分頁，`beforeunload` 對話框出現（附錄 A.4）。
- **服務要結束**：見 §3.8（分頁先存再放開）。
- 沒有「另存」：校稿資料只有一份（`session.json`），定稿檔另外產生（§7）。

### 6.5 校正版被 Pro 重跑覆蓋

- 開啟時比對 `transcript.corrected.md`（或 `transcript.md`）的 `sha256` 與 `session.source.sha256`。不同 → `changed`：
  - 畫面顯示**開始校稿時的版本**（`.proofread/source.md`）並唯讀，橫幅：「校正版逐字稿在上次校稿之後被重新產生（例如重跑了 AI 校正）。下面是開始校稿時的版本，只能看。」
  - 按鈕「用新版重新開始，帶入對得上的決定」與「用新版重新開始」：舊 `session.json`、`source.md` 改名備份；新 `session.json` 的 `rev` 接續舊值＋1。
  - 帶入規則：標記決定以（段落時間、講者、種類、原文、建議、推測）完全相同才帶，同一組有多處時依出現順序一一對應；人工修改以同段（時間＋講者）內第一個相同原文的位置帶入，並通過 §5.5 的檢查。帶入結果顯示「標記決定 a／b 處、人工修改 c／d 處」。
  - 校正版被重跑時 Pro 會把舊檔改名為 `transcript.corrected.<時間>.bak.md`（Pro 2.2.0 `auto_correct.py`）；工具不依賴它，以自己的 `source.md` 為準。
- `changed` 期間的暫存請求回 `409 source_changed`。
- 〔規格確認〕改動一段後偵測、擋存檔、帶入 14／14 處決定與 3／3 處人工修改（附錄 A.2）。

### 6.6 接續

- 關掉分頁或服務結束後，再從任何入口開同一份稿 → 讀 `session.json`，所有決定、人工修改、復原歷史都在；畫面捲到第一個未處理的標記。
- **接續提示**：稿上方的藍色橫幅「接續上次的校稿：上次儲存 YYYY-MM-DD HH:MM、已處理 n／N 處。」（「知道了」關閉）；首頁「最近的稿」卡片寫「上次儲存 YYYY-MM-DD HH:MM」與進度條「已處理 n／N（p%）」（還沒存過的寫「上次開啟 …（還沒有儲存）」）。
- 〔規格確認〕服務結束後重新開啟：新服務、暫存的決定 14 筆、人工修改 3 筆都在（附錄 A.2）；截圖 `resume-1440-dark.png`、`home-1440-dark.png`。

### 6.7 最近的稿

`state/recent.json`：`[{"id", "dir", "name", "opened_at", "saved_at", "progress"}]`，最多 20 份，開啟或暫存時更新到最前面（開啟時從該稿的 `session.json` 帶 `saved_at` 與 `progress`）。
首頁「接續」只能開這份清單裡的 id；資料夾已搬移或刪除 → 「這份稿的資料夾找不到了（可能已搬移或刪除）」。

### 6.8 操作紀錄

- `session.json` 的 `log`：每筆 `{"at", "action", "files": [檔名…], "note"?}`，保留最後 500 筆。**只記時間、動作、檔名、筆數**，不記逐字稿文字、詞對內容、權杖。
- 記錄的動作：開始校稿、儲存（手動）、儲存（離開分頁）、儲存（服務關閉）、定稿（含「部分失敗」）、名詞同步到會議記錄、重做會議記錄（含費用）、匯入對照表與詞表（筆數）、
  復原上次匯入、用新版重新開始（帶入／不帶入、舊暫存備份檔名）。自動暫存不逐筆記（每 1.2 秒一次會淹沒紀錄；最後一次見狀態列）。
- 查看：側欄「紀錄」分頁（頂端列也有「紀錄」按鈕），新的在上：時間（MM-DD HH:MM）、動作（附筆數）、檔名；上方寫「上次儲存 …（版本 n）」。API：`GET /api/doc/<id>/log`。
- 〔規格確認〕整合測試確認紀錄有上列各動作、而且不含逐字稿文字（附錄 A.2）；截圖 `log-1440-dark.png`。

## 7. 定稿

### 7.1 `transcript.final.md`

```markdown
# 定稿逐字稿：<來源檔名>

> 原始逐字稿：`transcript.md`（未修改）｜校正版：`transcript.corrected.md`｜定稿：會議記錄校稿 1.0.0，2026-11-08 11:20
> 校稿：標記 14 處（確認 13、改 0、退回 1、未處理 0）、人工修改 3 處

## 講者對應

| 代號 | 姓名 | 依據 |
|---|---|---|
| S1 | 王小明 | … |

---

**[00:00:00] 王小明（S1）**：好，我們開始。今天主要確認星河物流倉儲系統升級的進度……
```

- 本文段落格式與校正版相同（`**[HH:MM:SS] 講者**：本文`），**沒有任何標記**；Pro 的 `auto_minutes.parse_paragraphs(text, corrected=True)` 可以直接讀（讀 `---` 之後、沒有標記可換）。
- 不含〈校正摘要〉〈待確認〉（已由校稿處理）；其他本文行（畫面行、註記）原樣保留。
- 再次定稿：舊檔改名 `transcript.final.<時間>.bak.md` 後寫新檔。

### 7.2 定稿字幕 `transcript.final.srt`

- 做法：把每段寫成「所有標記都換成 `{原文→定稿文字}`」的校正版格式（人工修改同樣寫成標記；未處理的待確認保留 `[?原文｜推測]`），交給 Pro 的
  `subtitles.map_corrected(transcript.json, 文字, "orig")` 對回辨識段，再 `recue()` 依字幕規則切條、`render_srt()` 輸出；字幕選項用 Pro `subtitles.options(load_config())`（與 `transcript.corrected.srt` 一致）。
- **字數改變時怎麼對**（沿用 Pro 2.0.0 規格 §5.2 的對時規則，工具不另訂）：
  1. 標記以外的文字逐字歸給所在的辨識段（不變式 §5.5 保證成立）。
  2. 標記的定稿文字**整段放進原文起點所在的辨識段**，所以修正比原文長或短都不會讓後面的時間位移；原文跨兩個辨識段時記為「跨段標記」。
  3. 補字放進前一個字所在的辨識段；被刪光的辨識段不輸出。
  4. 一個辨識段切成多條字幕時，時間依內容字元數比例分配（Pro `recue`）。
  5. 某段對應失敗 → 該段用原文（Pro 行為），定稿結果顯示「定稿字幕：對應失敗 N 段，該段用原文」。
- 沒有 `transcript.json`（或沒有 segments）→ 不產生字幕，顯示原因。
- 〔規格確認〕用 Pro 2.2.0 的 `map_corrected` 對三份合成稿：對應失敗 0 段（附錄 A.2、A.6）。

### 7.3 還有未處理的標記時

定稿按鈕預設要求 0 處未處理；有未處理時顯示「還有 N 處未處理。仍要定稿時：校正、用字統一照建議；待確認寫成『原文〔?推測〕』，字幕用原文」與勾選「仍要定稿」（同 Pro 摘要讀校正版的方式）。

### 7.4 名詞寫法同步到會議記錄／筆記

- 定稿後列出「校稿確認的寫法，在會議記錄／筆記裡還是舊寫法的地方」：
  - 詞對：有決定、定稿文字≠原文、原文 ≥ 2 字、不是刪除的標記與人工修改（同一原文只取第一組）；加上已確認的用字統一（原文→統一）。
  - 對 `meeting-minutes.md` 與 `notes.md` 試套用，列出有出現的「舊寫法 → 新寫法、處數、檔案」，預設全部勾選。
- 套用：單次掃描替換（長的先比，同 Pro `corrections.Corrector`），`>` 開頭的說明行與 ``` 區塊不改；改過的檔先改名 `<主檔名>.<時間>.bak.md`（同 Pro `consistency.run_folder`）。
- 網頁版：該檔有同名 `.html` 時呼叫 Pro `render_html.render(輸出資料夾, 檔名, cfg=load_config())` 重新產生。
- 只改名詞寫法，不改摘要本文的其他內容。
- 按「同步勾選的寫法…」→ 確認畫面（每個檔改幾處、備份檔名、網頁版重產）→ 結果畫面（§7.6）。
- 〔規格確認〕D1 合成稿預覽 4 組、改 6 處、舊檔備份；用 Pro 2.2.0 `render_html` 重產網頁版成功（附錄 A.2）。

### 7.5 用定稿重做會議記錄／筆記（選用、要花費）

- 需要 Pro ≥ 2.3.0（§10.1）。按鈕「重做會議記錄（要花費）」（內容類型不是會議時寫「重做筆記」）。
- 按下 → 先執行 `auto_minutes.py <輸出資料夾> --source final --estimate-only` 取得預估（供應商、模型、費用區間），確認對話框顯示「會用 transcript.final.md 重新整理，舊的會議記錄改名備份。預估：<供應商> <模型>、約 US$x～y」與「重做（要花費）」「取消」。
- 確認後在背景執行（不經 shell，參數陣列；環境變數 `MEETING_MINUTES_PRO_HOME`、`PYTHONUTF8=1`）：

  ```
  <Pro python> -B $MMH/scripts/auto_minutes.py <輸出資料夾> --source final --force
  ```

  供應商、模型、通道、內容類型、範本都用 Pro 的設定與 `transcript.json` 的 meta（與使用者從右鍵整理時相同）。
- 進度：畫面輪詢工作狀態（每秒），「整理中…（可以繼續做別的事）」；完成後讀 stdout 最後一行的 JSON（`{"minutes": {...}}`）顯示結果、檔名、網頁版狀態、實際費用（Pro 執行 log 的等價費用）。
- exit code 對應 Pro：0 完成（ok／partial）、2 跳過（顯示原因）、3 登入失敗、4 模型不存在、5 其他失敗（顯示 Pro 的訊息）。
- **網頁版**：Pro 2.1.0 起 `auto_minutes.py` 寫完 `.md` 後就會依 `html.enabled` 產生 `meeting-minutes.html`／`notes.html`（「重做時也重產網頁版」由 Pro 完成，工具不另外呼叫）。
- 同一份稿同時只能有一個重做工作；執行中服務不會閒置結束（§3.8）。
- 〔規格確認〕試作是**假的呼叫**（不呼叫模型，只在會議記錄加一行說明並重產網頁版），示範流程與畫面（附錄 A.2）。

### 7.6 寫入動作的確認畫面與結果畫面

定稿是使用者按「定稿…」才做，**不會自動覆蓋 `transcript.corrected.md`**；所有會寫到「暫存以外」的檔的動作，都照同一個兩段式流程：

1. **確認畫面**（按下按鈕後先呼叫同一個 API 的試跑 `{"dry_run": true}`：伺服器只計算、不寫任何檔）：標題是問句（「定稿？」），一段說明，一張表「檔案｜內容｜先備份到」，再加上該動作的補充；按鈕「取消」與動作名稱（「定稿」「匯入（先備份）」「同步（先備份）」「重做（要花費）」）。
2. **結果畫面**（正式執行後）：標題（「✓ 已定稿」，部分失敗時「定稿部分完成」），一張表「檔案｜結果｜備份」列**實際寫入**的每個檔（筆數、處數、條數、對時方式）與實際的備份檔名；
   有失敗時，紅框列「沒有完成的部分（上面列的已經寫入；下面的沒有寫入）」與每個檔的原因；按鈕「開啟資料夾」（§4.4）與「關閉」。
3. 試跑或執行整個失敗（沒有寫入任何檔）：對話框「沒有寫入任何檔案。原因：…」。**不得默默失敗**：任何寫入錯誤都要出現在結果畫面或這個對話框。

| 動作 | 確認畫面列出 | 結果畫面列出 | 「開啟資料夾」開哪裡 |
|---|---|---|---|
| 定稿（§7.1～§7.3） | `transcript.final.md`（N 段）、`transcript.final.srt`（定稿字幕；沒有 `transcript.json` 時不列）、已有的舊檔要改名成的 `.bak` 檔名；「不會改 transcript.md、transcript.corrected.md」；已處理 n／N、未處理的寫法 | 兩個檔的段數、字幕條數與對時方式（Pro `map_corrected`、對應失敗 N 段）、備份檔名 | 輸出資料夾 |
| 名詞同步（§7.4） | 每個 `.md` 改幾處、備份檔名；有網頁版的 `.html`（重新產生、不另備份） | 每個 `.md` 實際改幾處與備份檔名；`.html` 重產成功或失敗原因 | 輸出資料夾 |
| 重做會議記錄／筆記（§7.5） | 要寫的 `.md`（舊檔備份名）與 `.html`；黃框「供應商：<供應商> <模型>（<通道>）；費用估算：約 US$x～y」 | 寫入的 `.md`、備份、`.html`；實際費用；失敗時 Pro 的訊息 | 輸出資料夾 |
| 匯入對照表與詞表（§8.5） | `$MMH/corrections.tsv`（N 筆，檔尾加入）、`$MMH/glossary.txt`（M 個）、備份到 `$MMH/backups/corrections.<時間>.tsv`／`glossary.<時間>.txt`（原本沒有檔時寫「不用備份」）；要匯入的詞對與詞 | 實際寫入的筆數與備份檔名；「下次轉寫時生效、可按『復原上次匯入』」 | `$MMH` |
| 復原上次匯入（§8.7） | 要還原的檔、從哪個備份還原（或「原本沒有這個檔：刪除」） | 已還原的檔 | `$MMH` |

- 畫面上的路徑一律寫成相對位置（輸出資料夾裡的檔名、`$MMH/…`），不顯示使用者電腦的完整路徑（截圖與分享不洩漏帳號名稱）；需要看實際位置就按「開啟資料夾」。
- 試跑與正式執行之間檔案可能改變：正式執行以當下狀態為準，結果畫面列的是實際寫入的（例如試跑時沒有舊檔、正式執行時有了，結果畫面就會多列備份）。
- 〔規格確認〕試跑不寫檔、正式結果的檔名與備份、再次定稿的舊檔備份都有整合測試（附錄 A.2）；截圖 `final-confirm`、`final-result`、`sync-confirm`、`redo-confirm`、`redo-result`、`import-confirm`、`import-result`。

## 8. 經驗整理（校稿經驗匯入對照表與詞表）

### 8.1 從哪裡整理

- 對照表建議的來源：每個**有決定**（或人工修改）而且定稿文字≠原文的標記，得到詞對（原文, 定稿文字）；同一詞對累計處數。
  - 包含：校正（接受或自由輸入）、刪除、待確認（選推測或自由輸入）、人工修改。
  - 不含：用字統一（Pro 規則：統一不進對照表建議，規格 2.2.0 §14；改進詞表，§8.4）、補字（沒有原文）、退回（定稿＝原文）、未處理。
- 原文在整篇出現的次數：數 `transcript.md` 本文（段落）的出現次數（同 Pro `build_suggestions` 用 `orig_text.count(a)`）。

### 8.2 預設勾選的條件（與 Pro 固定錯誤條件一致）

一個詞對**全部符合**下列條件才預設勾選；不符合的照樣列出、不勾，並寫出原因：

| # | 條件 | 對應 Pro | 不符合時顯示 | 能否手動勾 |
|---|---|---|---|---|
| 1 | 原文 ≥ 2 字 | §6.10「長度至少 2 字」、`corrections.MIN_LEN` | 太短（少於 2 字） | 可 |
| 2 | 不是刪除（定稿文字非空） | `build_suggestions`「長度或刪除」 | 刪除 | 可 |
| 3 | **固定**：原文每次出現都改成同一個寫法（原文出現次數＝這個詞對的處數，且沒有其他寫法） | §6.10「固定」、「不是每次都改」 | 不是每處都改成這個寫法（原文 X 處、改 Y 處） | 可 |
| 4 | 本場至少出現 `correction.corrections_auto.min_count` 次（Pro 設定，預設 2） | 條件式自動寫入 ①（同一門檻，避免一次性口誤進表） | 本場只出現 1 次 | 可 |
| 5 | **不衝突**：定稿文字不是對照表的錯誤寫法、原文不是對照表的正確寫法 | §6.10「不衝突」 | 與對照表衝突 | **不可**（§8.6） |
| 6 | 原文不在 OpenCC 詞彙回復表（Pro `opencc_keep.load_merged()`） | `build_suggestions`「回復表的詞」 | OpenCC 回復表的詞 | 可 |
| 7 | 原文不在 `glossary.txt` | `build_suggestions`「glossary 的詞」 | 詞表裡的詞 | 可 |
| 8 | **非一般詞**：原文不是一般英文單字（Pro `consistency.COMMON_WORDS`） | §6.10「非一般詞」 | 一般英文單字 | 可 |

- 〔規格決定〕不套用 Pro 自動寫入的「② 累計場次」「③ 用字表 high」「④ 模型清單」「⑤ 每場上限」：那幾條是在**沒有人確認**時保護對照表；校稿是使用者逐處確認過、而且匯入前還要再勾選。
- 已經在對照表的詞對（錯誤與正確寫法都相同）：列出、標「已在對照表」、不能勾。
- 〔規格確認〕D1 合成稿：星荷→星河（3／3）、瑞迪斯→Redis（2／2）、退幣→退避（人工 2／2）預設勾；全線→權限（原文 2 處、改 1 處）、密等→冪等（1 次）、謝謝觀看→（刪除）、七月三號→七月十三號（1 次）不勾並列原因（附錄 A.2）。

### 8.3 詞與片語

- 「片語」：原文或定稿文字含空格，或原文的內容字元（去空白與標點）≥ 5 個；其他是「詞」。只是標示（清單上分開顯示），條件與匯入方式相同。
- 對照表本來就支援多字的錯誤寫法（Pro `Corrector` 長的先比），片語照樣寫進 `corrections.tsv`。

### 8.4 詞表（`glossary.txt`）建議

- 候選：詞對的定稿文字中「寫法有特徵的英文名詞」（含大寫字母，例 `Redis`、`NotebookLM`）與人工修改的定稿文字（≥ 2 個內容字元），加上已確認的用字統一的標準寫法；已在詞表的不列。
- 預設勾選：英文名詞而且不是一般英文單字；中文詞預設不勾（「中文詞預設不勾，確認是專有名詞再勾」）。
- 用途：詞表是 Pro 轉寫的 hotwords 與用字統一標準寫法的第一優先（Pro 2.2.0 `consistency.user_terms()`）。

### 8.5 匯入格式與備份

- 匯入前備份（同一個時間戳）：
  - `corrections.tsv` → Pro `corrections.backup(stamp)`（`$MMH/backups/corrections.<時間>.tsv`）。
  - `glossary.txt` → `$MMH/backups/glossary.<時間>.txt`（同樣的命名規則；同名已存在時加 `-1`、`-2`）。
  - 檔案原本不存在：不備份，紀錄寫「（原本沒有這個檔）」。
- 寫入：
  - 對照表：Pro `corrections.append_rows()`（檔尾追加，保留使用者原本的註解與排版；檔案不存在時先寫表頭），每列 `錯誤寫法<TAB>正確寫法<TAB>proofread:<YYYY-MM-DD> <來源檔名>`。
    〔規格決定〕備註前綴用 `proofread:`，與 Pro 自動寫入的 `auto:` 區分：Pro 的 `corrections.py auto-undo` 不會動到校稿匯入的列，校稿匯入用工具自己的復原（§8.7）。
  - 詞表：檔尾追加，一行一詞。
- 伺服器重新計算一次建議，只接受「目前建議清單中、可匯入」的項目（前端送來的其他項目忽略）。
- 按「匯入勾選的項目…」→ 確認畫面 → 結果畫面（§7.6）：確認畫面列要寫的檔、筆數、備份位置與要匯入的詞對；結果畫面列實際寫入的筆數與備份檔名、「下次轉寫時生效」，「開啟資料夾」開 `$MMH`。
- 匯入紀錄寫進 `session.json` 的 `imports`（詞對、詞、備份路徑、匯入後兩個檔的 `sha256`）。

### 8.6 去重與衝突

| 情況 | 處理 |
|---|---|
| 詞對已在對照表 | 「已在對照表」，不能勾 |
| 原文已在對照表、但正確寫法不同 | 「對照表已有『原文 → 其他寫法』」，**不能勾**〔規格決定：要改既有項目請用 `corrections.py add … --force`，避免校稿一次就覆蓋長期累積的寫法〕 |
| 定稿文字是對照表的錯誤寫法，或原文是對照表的正確寫法 | 「與對照表衝突」，不能勾（會造成互相替換） |
| 同一次勾了同一原文的兩種寫法 | 不會發生：同一原文有兩種寫法時條件 3 不成立；就算手動勾，伺服器只寫第一組並在結果列出略過的 |
| 詞表重複 | 已在詞表的不列入建議 |

### 8.7 復原上次匯入

- 「復原上次匯入」：只在兩個檔目前的 `sha256` 等於匯入後記錄的值時，用備份還原（原本不存在的檔就刪除）；否則顯示「corrections.tsv 在匯入後又被改過，不能自動復原；備份在 backups/」。
- 復原後從 `imports` 移除該筆。
- 〔規格確認〕匯入 3 筆＋1 個詞、備份與匯入前相同；再整理時同一筆顯示「已在對照表」；復原後檔案與匯入前逐位元相同（附錄 A.2）。

### 9.8 播放器（沿用 2.1 網頁版）

- 媒體檔依 Pro 2.1 `render_html.find_media` 的順序找：① `<輸出資料夾>/../<meta.source>` ② `<輸出資料夾>/<meta.source>` ③ `<名稱>_minutes` 旁同名的媒體（2.1 規格 §5.3 的副檔名表，大小寫不分）；
  瀏覽器不能播的格式顯示「原始檔格式 <副檔名> 瀏覽器多半不能播放，時間碼以文字顯示」。
- 服務以 `/api/doc/<id>/media` 提供（支援 `Range`，可拖曳進度），不給前端任何路徑。

### 9.9 長逐字稿效能（2～3 小時）

- 目標（實作驗收）：3 小時稿（約 900 段、1,000 處標記）在一般筆電上開啟到可操作 < 2 秒；每次決定（含重畫段落、更新進度與目錄）< 50 ms；暫存 < 200 ms。
- 做法：一次渲染全部段落並用 `content-visibility: auto`；決定只重畫該段；標記清單一次最多列 400 筆（「請用篩選縮小」）；暫存送整份 JSON（< 1 MB）。
- 〔規格確認〕試作：開啟 74 ms、每次接受 24 ms（附錄 A.5）。

### 10.2 不需要 Pro 補的

- **標記解析共用模組**：不新增。工具直接 import Pro 已有的 `consistency.MARK_RE`、`key_of`、`subtitles.*`、`corrections.*`、`render_html.render`（§2.2 介面檢查保證相容）。
  理由：Pro 的這些函式已有測試、已凍結；另抽共用模組會讓 Pro 為了工具改結構，反而增加兩邊互相等待。
- **右鍵入口共用**：不共用。工具自己的「傳送到 → 會議記錄校稿」與 Pro 的「會議轉寫（Pro）」並列；兩個入口目的不同（轉寫 vs 校稿），各自安裝、各自移除。

### 10.3 避免兩邊版本卡住

1. 工具 1.0.0 的最低需求是 **Pro 2.2.0**（已發布），不需要等 Pro 2.3.0 才能發；只有「重做會議記錄」在 Pro 2.2.x 上停用（§2.4）。
2. Pro 2.3.0 不依賴工具（P1、P2 對沒裝工具的使用者也有用；P3、P4 在沒裝工具時什麼都不做）。
3. 介面檢查（§2.2）在每次啟動時做，Pro 之後若改了介面，工具會明確提示不相容，而不是寫壞檔案。
4. 發版順序不限：工具 1.0.0 可以先發，Pro 2.3.0 照 Pro 自己的排程；Portal 相容表隨兩邊發版更新。

#### ⑤ 設計理念：`site/design/index.md` 加一節〔規格決定：加在既有頁，不另開頁〕

理由：設計理念頁是一份編號清單（目前 1～11），校稿的取捨放在同一份裡，讀者看得出它延續同一套原則（本機優先、看得到、可回頭）。

- 在第 11 節之後加 `## 12. 會議記錄校稿為什麼這樣做`，小節：
  1. `### 本機網頁應用程式，而不是桌面 App 或純 HTML`：桌面 App 要分平台打包與 macOS 簽章公證；純 HTML 在 Safari／Firefox 不能寫回檔案；瀏覽器每部電腦都有，Python 已隨 Pro 裝好，不多裝東西。
  2. `### 一鍵開啟，不碰伺服器`：服務是程式內建、自動開關；右鍵或雙擊就好。
  3. `### 只有一個本機服務`：多份同時時不會開出一堆連接埠與視窗，也才能防止同一份稿被兩處同時改。
  4. `### 每個寫入動作都看得到`：存檔狀態列、確認與結果畫面、操作紀錄。
  5. `### 定稿不覆蓋校正版`：AI 的修改紀錄（校正版）與人的決定（定稿）分開保存，隨時能回頭比對；原始逐字稿一字不改的原則延伸。
  6. `### 經驗要勾選才匯入`：對照表會影響之後每一場轉寫；一次性的口誤寫進去會越用越錯，所以只預設勾「每次都錯成同一個樣子」的，並且先備份、可復原。
  7. `### 安全與隱私`：只綁 127.0.0.1、一次性權杖、只能開被傳進來的資料夾、不載入任何外部資源、不連網；防火牆不會跳提示的原因。
- 頁首 `description` 與「這頁幫你了解」補一句「也說明會議記錄校稿的設計取捨」。

### 11.2 `mm-release.json` 新欄位與讀法

```json
{
  "proofreadVersion": "1.0.0",
  "proofreadTag": "proofread-v1.0.0",
  "proofreadMinPro": "2.2.0",
  "proofreadReleasedAt": "<發布日>",
  "assets": {
    "proofread": [ { "name": "meeting-minutes-proofread-v1.0.0-installer.zip", "sha256": "<64 碼>" } ]
  }
}
```

- 既有欄位（`proVersion`、`basicVersion`、`releasedAt`…）不改名不移除；`releasedAt` 仍代表 Pro／基本版那一輪。
- `.vitepress/config.mts`：`MmRelease` 型別加上面四個欄位與 `assets.proofread`；`readRelease()` 檢查四個欄位都有、`proofreadTag === 'proofread-v' + proofreadVersion`（缺了就建站失敗，同現有做法）。
- 元件：
  - `ReleaseDownload.vue` 的 `product` 加 `'proofread'`：標題「會議記錄校稿（Pro 的附屬工具）」、版號 `proofreadVersion`、發布日 `proofreadReleasedAt`、tag `proofreadTag`、附件 `assets.proofread`（只有安裝包，沒有上傳版）；下載網址同樣是 `releasesUrl + download/<tag>/<檔名>`。
  - `MmVersion.vue` 的 `product` 加 `'proofread'`（→ `proofreadVersion`）與 `'proofread-min-pro'`（→ `proofreadMinPro`）。
  - 新元件 `ProofreadIntro.vue`（首頁，§11.1 ①），內部用 `ReleaseDownload product="proofread" compact`。
- 首頁讀 `proofreadVersion`（按鈕上的版號）與 `proofreadMinPro`（「要先安裝 Pro X 以上」）；安裝頁讀全部欄位（下載區、相容表目前列）。
- 頁尾「內容基準」一行加「、會議記錄校稿 <proofreadVersion>」。
- Release 網址前綴已是 repo 的 `releases/`，新 tag 不必改允許清單；`lychee.toml` 不需調整。

### 11.5 發版流程

同一輪：(1) 匯出公開 repo（允許清單、去識別掃描 0、一般 push）→ (2) Portal 更新（工具頁、安裝頁、更版紀錄、`mm-release.json`），`npm ci && npm run build` exit 0 才推送 →
(3) Release `proofread-v<版號>`（`--latest=false`），附件掃描 0 才上傳。

## 12. 測試計畫
