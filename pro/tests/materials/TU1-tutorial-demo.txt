S1｜大家好，這一段示範要教大家，怎麼在我們的專案裡面開一個功能分支，改完之後發合併請求，請同事審查。整個流程大概十分鐘，大家可以開著自己的終端機一起做。開始之前，請先確認兩件事：第一，你已經把專案 clone 下來；第二，你的 Git 版本是二點四十以上，可以打 git --version 看。
S1｜<2.5>第一步，先把主分支更新到最新。切到 main，然後打 git pull。這一步很重要，如果你從舊的 main 開分支，之後合併的時候很容易衝突。
S1｜<3.0>第二步，開一個新的功能分支。打 git switch 空格 -c，後面接分支名稱。我們的命名規則是 feature 斜線，加上工單編號，再加上簡短的英文描述，例如 feature/OPS-214-export-csv。工單編號一定要有，這樣系統才會自動把分支連到工單。
S2｜補充一下，分支名稱不要用中文，也不要有空白，有些自動化的腳本會讀不到。
S1｜對，謝謝承翰。
S1｜<4.0>第三步，修改程式。這邊我示範改一個很小的地方，在匯出的函式裡面加一個 CSV 的選項。改完以後，先打 git status，看看哪些檔案被改了，確認沒有不小心改到別的檔案。
S1｜<3.0>第四步，把改好的檔案加進暫存區，然後提交。打 git add，後面接檔案名稱，盡量不要用 git add 點，因為很容易把設定檔或暫存檔一起加進去。提交的時候打 git commit 空格 -m，後面是提交訊息。
S1｜提交訊息的規則是：第一行寫類型加冒號，再加一句話說明，例如 feat 冒號 export orders as CSV。類型常用的有 feat 是新功能、fix 是修錯、docs 是文件。第一行不要超過七十二個字元。
S2｜老師，如果提交訊息打錯了，還沒推上去，可以改嗎？
S1｜可以。還沒推上去的話，打 git commit 空格 --amend，就可以改最後一次提交的訊息。但是已經推上去、別人也拉下來的，就不要用 amend 了，會讓大家的歷史對不起來。
S1｜<3.5>第五步，把分支推到遠端。第一次推的時候要打 git push 空格 -u origin，後面接分支名稱，-u 是讓本機分支跟遠端分支連起來，之後只要打 git push 就好。
S1｜<4.5>第六步，到網頁上開合併請求。推上去以後，終端機會出現一個連結，點進去就是開合併請求的頁面。標題沿用提交訊息，說明欄要寫三件事：改了什麼、為什麼改、怎麼測試。審查者至少選一位，目標分支選 main。
S1｜這裡有一個常見的錯誤：目標分支選錯，選成別人的功能分支。送出之前，請再看一次頁面上方，確認是從你的分支合併到 main。
S1｜<3.0>第七步，如果審查的時候出現衝突，代表 main 在這段時間有別人改到同一個地方。這時候回到終端機，打 git pull 空格 --rebase origin main，把你的修改接到最新的 main 後面。有衝突的檔案，Git 會標出來，改完以後打 git add，再打 git rebase 空格 --continue。
S2｜rebase 完要推上去的時候，一般的 push 會被拒絕，要用 git push 空格 --force-with-lease，不要用 --force，這樣如果遠端有別人新推的東西，它會擋下來，不會蓋掉。
S1｜<3.0>最後一步，審查通過、合併以後，記得把分支刪掉。網頁上合併的時候可以勾「合併後刪除分支」，本機的分支打 git branch 空格 -d，加上分支名稱。
S1｜好，我們來確認一下有沒有做成功：回到網頁，合併請求的狀態應該是「已合併」，工單頁面也會自動出現這個分支的連結。如果工單上沒有出現，通常是分支名稱沒有寫工單編號。今天的示範就到這裡，有問題可以在頻道上問承翰或我。
