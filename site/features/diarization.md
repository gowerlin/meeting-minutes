# 說話者分離與講者人數

**這頁幫你做到**：轉寫前「講者人數」那一題答得對，看懂逐字稿裡的 S1、S2 與 ⚠ 標示。

**說話者分離**是依聲音把逐字稿分成 S1、S2、S3…（第 1 位、第 2 位、第 3 位講者…）的步驟。它只知道「這是不同的聲音」，不知道名字；把 S1 對應到真實姓名，要靠 AI 從對話內容推斷，或由你提供與會名單。

## 講者人數那一題

```text
講者人數（Enter＝自動判斷；填實際人數，不確定就留空；輸入 s＝略過說話者分離）：
```

| 你輸入 | 意思 |
|---|---|
| 直接按 Enter | 自動判斷人數 |
| 1～20 | 實際人數。程式自動分群之後，**保留發言最多的 N 位**，其他零星的代號併進時間上相鄰的講者 |
| `s` | 略過說話者分離：全部標成同一位講者 `S?`，比較快 |

::: tip 填實際人數，不確定就留空
填得比實際少，多出來的那位會被併進別人。不確定時留空，讓程式自動判斷，之後再看 ⚠ 標示處理。
:::

「人數 1」不是略過：程式照常分離，最後只保留一位。

## 零星講者的 ⚠

沒有填人數時，程式不會自動合併任何代號。逐字稿 `transcript.md` 開頭會多一行「講者發言時間」，**總發言少於 10 秒**的代號會標「⚠ 發言很少，可能是分離誤判」，結束畫面也會提醒。

處理方式（二選一）：

- 確定人數後重新轉寫，這次填人數。
- 在 Claude 對話中直接說「S5、S6 是 S2」。

## 略過說話者分離的代價

單人錄音（例如自己錄的講課）可以輸入 `s` 略過，比較快。代價是：

- 字幕的時間比較不準（段首誤差約 0.8 秒，分離時約 0.1 秒）。
- 學員提問會併進講師的段落。
- 筆記的涵蓋率略降。

課程、操作教學的題目會特別提示這個選項。

## 講者太多或太少

| 狀況 | 怎麼辦 |
|---|---|
| 很多發言很少的代號（⚠） | 多半是分離誤判：重跑並填實際人數，或把分群門檻調大 |
| 兩個人被併成一個 | 把分群門檻調小（例如 `--cluster-threshold 0.8`）；有 NVIDIA 顯示卡可以改用 GPU 說話者分離 |

**分群門檻**（只影響 CPU 說話者分離；數字越大，判斷出的講者越少）：預設 0.9，課程 1.0、座談 0.8。可以在 `config.json` 的 `diarization.cluster_threshold` 改共用值，或用 `content_types.<代號>.cluster_threshold` 改某一種類型。

::: warning 這些預設值只用合成素材調過
門檻與「保留前 N 位」都是用 3～5 位講者的語音合成素材調出來的。真實錄音（多人搶話、遠距收音、長時間會議）會不會一樣改善，還沒有驗證。真實錄音常見的情況是講者被分成比實際多很多位，這時請填實際人數。
:::

## GPU 與 CPU 怎麼選

| | CPU（預設） | GPU（選裝，Windows＋NVIDIA） |
|---|---|---|
| 引擎 | sherpa-onnx | pyannote `speaker-diarization-community-1` |
| 速度（每小時錄音） | 約 3.5 分鐘 | 約 1.5 分鐘 |
| 門檻 | 可以調 | 不能調（人數照樣可以填） |
| 合成素材上的表現 | 座談素材 5 位全對 | 會議、課程、訪談判得比較準；座談把只講 11 秒的觀眾併掉，工作坊多分出 2 位 |

- 裝好 GPU 版後，`auto`（預設）會在顯示卡可用記憶體 ≥ 4 GB 時用 GPU，否則用 CPU；GPU 這次失敗會自動改用 CPU。
- **座談預設用 CPU**。想讓座談也用 GPU，或任何類型單次指定，轉寫時加 `--diarize-engine pyannote`（或 `sherpa`）。
- 用了哪個引擎、為什麼：看 `transcript.json` 的 `meta.diarization`，或[執行 log](/features/run-log) 彙整表的「分離」欄。

安裝方式見 [GPU 說話者分離（選用）](/install/gpu)，背後的取捨見[研究方法](/design/research#gpu-與-cpu-說話者分離的取捨)。
