# 設計理念

**這頁幫你了解**：這套工具為什麼長成現在的樣子，包括機敏會議為什麼用「拒絕」而不是「提醒」（[本機限定](#local-only)），也說明會議記錄校稿的設計取捨。功能清單見[功能總覽](/features/)；設計背後的實測方法與數字見[研究方法](/design/research)。

## 1. 錄音留在你的電腦上

會議錄音常常含有不該外流的內容，所以**轉寫一律在本機完成**：語音辨識、說話者分離、分段標點、繁體轉換、截圖，全都在你的電腦上跑，不連網、不上傳。

- **硬體在安裝時就選好**：安裝程式把你電腦上能用的方式（Intel NPU／GPU、NVIDIA、Apple Silicon、CPU）都拿同一段錄音試跑，記下最快的那個。轉寫時不再偵測，直接照記錄執行，所以每次都穩定、可預期。沒有加速硬體也能用，只是比較慢。
- **NPU 與 Apple GPU 優先**：只要速度在最快者的 1.25 倍以內，就優先選它們，省電，也把 CPU 讓給你正在做的事。
- **安裝完就能離線**：模型在安裝時下載好，之後轉寫不需要網路。

## 2. AI 是選用的，而且你每次都知道送出了什麼

AI 校正與整理很好用，但要把逐字稿文字（AI 校正另有影片截圖與你放的參考資料）送到雲端。所以：

- **轉寫完才問**：先拿到完整的逐字稿，再決定要不要送。兩題都回答 n，你仍然有一份完整的逐字稿。
- **每一題都寫明**：這次要送什麼（逐字稿文字、幾張截圖、幾份文件的名詞與段落）、送到 GPT（OpenAI）還是 Claude（Anthropic）、預估多久、大約多少錢。
- **只送需要的部分**：音檔與文件原檔永遠不送。截圖只在 AI 校正時送、最多 8 張並縮小（為了認出與會者全名與會議日期，2.2 起），可以在設定裡關掉；會議摘要不送截圖。文件只送本機挑出的名詞與相關段落。
- **用你自己的帳號**：預設透過你電腦上已登入的 Codex 或 Claude Code，用你自己的訂閱額度；金鑰只從環境變數讀，不寫進任何檔。
- **AI 失敗不影響轉寫**：沒登入、額度用完、網路斷了，逐字稿照常完成，之後可以補做。
- **在 Claude 裡整理是另一條路**：在 Claude Code 或 Claude 桌面 App 的對話中整理時，你附上或讓 Claude 讀取的逐字稿與截圖會送到 Anthropic 的雲端由 Claude 處理（音檔不送），對話中沒有上面這種「要送出嗎？」的詢問；有機敏內容時請不要在對話中讀逐字稿，改用本機限定。
- **機敏會議可以完全不送**：用[本機限定](#local-only)（2.4 起），那一份的 AI 步驟一律拒絕，連問都不問。

## 3. 每一句都能回頭查證

AI 會出錯，語音辨識也會。設計的重點是**讓你能快速查證**，而不是假裝結果完美：

- **原始逐字稿永遠不改**：`transcript.md` 是辨識的原樣；校正寫在另一份 `transcript.corrected.md`，每一處修改都標成 `{原文→修正}`。
- **拿不準就不硬改**：AI 不確定的地方標成 `[?原文｜推測]`，留給你回聽決定；字幕裡預設顯示原文。
- **每一項都附時間碼**：決議、待辦、待釐清問題都能直接跳到錄音裡那一句。
- **不杜撰，並明白寫出來**：整理只寫錄音裡講到的；沒講期限就寫「未定」；表頭寫「自動整理｜未經人工確認」，提醒你這是草稿。
- **程式幫忙把關**：模型改了字卻沒標出來，程式會擋下那一段、放回原文；訪談的引述對不上原話會標 ⚠。

## 4. 越用越準

同一個團隊的會議，常常反覆出現同樣的人名、產品名與同樣的錯法。與其每次重新校正，不如把經驗存下來：

- **專有名詞清單**：事先告訴辨識模型會出現哪些詞。
- **固定錯誤對照表**：總是被聽錯的詞記成一張表，下次自動替換；正確寫法也會加進辨識提示。只放「固定的錯法」，要看上下文才知道對錯的同音字仍交給 AI。
- **你確認才寫入**：AI 只產生建議，預設由你確認後才加進對照表；選用的自動寫入也要同時符合多項嚴格條件，而且可以撤銷。
- **用語回復**：簡繁轉換會把「權限」改成「許可權」，程式先把台灣本來就在用的詞保護起來。

## 5. 同一套流程，套用不同用途

會議、課程、訪談、操作教學……錄音的轉寫步驟都一樣，差別只在最後要整理成什麼。所以用**內容類型**切換筆記的格式與少數參數（例如課程的講者通常只有一位、操作教學的截圖要比較靈敏），其餘流程共用。

**自訂範本只能改說法，不能改執行行為**：範本可以改名稱、節標題、補一段整理重點；但寫了模型、指令、要送出的檔案這類設定，整份範本不會載入；整理重點裡要求忽略規則或輸出整份逐字稿，AI 也不照做。這樣即使拿到別人寫的範本，也不會讓程式做出你沒預期的事。

## 6. 說話者分離：先求能用，再求更好

- **CPU 預設就能用**：不需要特別的硬體，也不需要任何帳號。
- **GPU 是選用的**：有 NVIDIA 顯示卡時可以加裝，比較快、多數情況比較準；但要下載約 5 GB，還要自己到 Hugging Face 同意模型作者的條件，所以預設不裝，裝失敗也不影響主程式。
- **依實測決定預設值**：例如座談素材上，GPU 會把只講了幾秒的觀眾發言併掉，CPU 反而分得對，所以座談預設用 CPU。
- **「講者人數」的意思改成「保留發言最多的 N 位」**：舊做法是強制分成 N 群，實測容易把一個人拆成兩個、又把兩個人併成一個；新做法先自然分群，再把零星的代號併進相鄰的講者，講者混淆大幅下降。
- **誠實標示可能的誤判**：發言很少的代號標 ⚠，請你判斷，而不是自動吞掉。

## 7. 字幕照規則切，而不是照辨識段落切

辨識的段落是給程式用的，常常一段好幾十個字，直接當字幕很難讀。所以另外照繁體中文字幕的通行規範（每行 16 字、最多 2 行、每條 5/6～7 秒）重新切條；AI 校正後的文字再對回原本的時間軸，產生校正版字幕。對不回的段落用原文，並告訴你有幾段。

## 8. 透明：每一次執行都留下紀錄

每次轉寫都記下各步驟花了多久、每一次模型呼叫用了多少 token、換算成 API 大約多少錢，可以彙整成表比較。**不記錄**逐字稿內容、金鑰與帳號資訊。這讓你知道「這場會議實際花了多少」，也讓日後的改版能用真實的數字比較。

## 9. 給不熟電腦的人

- **一鍵安裝**：雙擊一個檔，照選單回答；Python 與 ffmpeg 由系統的套件工具自動裝好。
- **白話的畫面訊息**：每一題都寫預設值與影響，例如「直接按 Enter＝會議」「填實際人數，不確定就留空」。
- **不出現嚇人的錯誤**：第一次執行時，還沒有「上次的選擇」這種正常情況，安靜地當作沒有，不印紅字。
- **失敗時退回、不中斷**：GPU 失敗改用 CPU、標點模型沒下載好仍會分段、AI 失敗仍有逐字稿；並在畫面上說明原因與怎麼補。
- **按錯鍵也不怕**：等待的幾分鐘裡不小心按到 Enter，不會被當成下一題的答案。

## 10. 升級不破壞你的東西

- **重新執行安裝程式就是升級**；你的專有名詞清單、對照表、自訂範本、設定、紀錄與模型都保留，設定只補上新的鍵。
- **入口與名稱不改**：右鍵選單、應用程式名稱、輸出資料夾的位置與既有檔名維持不變，升級後照原本的習慣用。
- **行為改變會明白寫出來**：例如 2.0 改了講者人數的意思、分群門檻的預設值，都列在[升級注意](/install/upgrade#從-1-x-升級到-2-0-要注意的事)，並告訴你怎麼回到舊的行為。

## 11. 為什麼不用本地 AI 模型做校正與整理

能在自己電腦上跑 AI 校正與整理，隱私上最理想，所以我們實際評估過。結果是：本地模型的校正修對率與雲端模型差了 60 個百分點以上，會議摘要漏掉的決議、待辦也多，還會出現雲端模型沒有的杜撰；而且要達到這個品質，顯示卡記憶體需要 16 GB 以上（較大的模型要 80 GB 以上），一般電腦達不到，速度也慢約 3 倍。因此現在的 AI 步驟只支援 GPT 與 Claude，並維持「選用、轉寫完才問」。

本地模型的品質與硬體門檻變化很快。當一般電腦就能跑、而且在同一套合成素材上達到校正修對 80%、錯改 5% 以內的門檻時，會再評估。評估方法與數字見[研究方法 › 本地模型評估](/design/research#本地模型評估-為什麼目前不列入)。

## 12. 會議記錄校稿為什麼這樣做

[會議記錄校稿](/features/proofread)延續同一套原則：本機優先、每個動作都看得到、隨時可以回頭。

### 本機網頁應用程式，而不是桌面 App 或純 HTML

桌面 App 要為每個平台分別打包，macOS 還要簽章公證；純 HTML 檔在 Safari、Firefox 裡不能把修改寫回檔案。瀏覽器每部電腦都有，Python 也已經隨 Pro 裝好，所以做成「在自己電腦上跑的小網頁服務」：不多裝任何東西，Windows 與 macOS 用同一套程式。

### 一鍵開啟，不碰伺服器

服務是程式內建的，開啟時自動啟動、所有分頁關掉約 3 分鐘後自動結束。你只要對輸出資料夾按右鍵，或雙擊資料夾裡的「會議記錄校稿.mmproof」，不必打指令、也不必管「伺服器」。

### 只有一個本機服務

同時校好幾份稿時，也只有一個服務、一個連接埠，每份稿一個分頁。這樣不會開出一堆視窗，也才能確保**同一份稿只在一個分頁被修改**：再開一次時只會出現提示頁，不會有兩個分頁同時改同一份稿、互相覆蓋。

### 每個寫入動作都看得到

頂端固定的存檔狀態列隨時告訴你「已儲存幾點幾分」或「儲存失敗、原因是什麼」；定稿、匯入、同步、重做都先出確認畫面（要寫哪些檔、先備份成什麼名字），做完再出結果畫面；側欄的操作紀錄列出每一次寫入。你不必猜程式做了什麼。

### 定稿不覆蓋校正版

原始逐字稿一字不改、AI 的修改另存校正版，這是 Pro 一直以來的原則。校稿再往下延伸一層：**人的決定另存成定稿**（`transcript.final.md`），校正版保持原樣，隨時能回頭比對 AI 改了什麼、人又改了什麼。

### 經驗要勾選才匯入

對照表會影響之後的每一場轉寫。一次性的口誤寫進去，之後每一場都會被「改」成錯的，越用越錯。所以只有「每次都錯成同一個樣子」的詞對會預設勾選，其餘列出原因讓你決定；匯入前先備份，也可以復原。

### 安全與隱私

- 服務只接受這部電腦本身（127.0.0.1）的連線，區網與網際網路都連不到，所以 Windows 防火牆不會跳出詢問。
- 開啟網址帶一次性的登入權杖（短時間內有效、用一次就失效），其他網頁無法操作這個工具。
- 每份稿只能讀寫它自己的輸出資料夾，以及 Pro 的對照表與詞表。
- 頁面不載入任何外部資源（字型、CDN、追蹤），校稿本身不連網。

## 13. 本機限定：機敏會議不上雲 {#local-only}

AI 校正與整理很方便，但有些會議的內容根本不該離開這部電腦：客戶個資、合約與報價、人事、還沒公開的財務或技術資料。對這些會議，「每次都先問、寫明要送什麼」（第 2 節）還不夠：人會趕時間，也會習慣性地按 Enter。所以 2.4 加了**本機限定**：那一份什麼都不送 GPT 或 Claude。

### 兩種開法

- **每份會議**：從另一個右鍵入口「會議轉寫（Pro，本機限定）」轉寫（macOS 是另一個拖放用的 app）。輸出資料夾會寫入標記檔 `local-only.json`，之後這一份的每一個步驟都認得它，包括會議記錄校稿。
- **整部電腦**：`config.json` 的 `privacy.local_only` 改成 `true`，每一份都不送。

平常的會議照常用 AI，機敏的那幾場換一個入口就好；整個部門都不能用雲端 AI 時，開全域設定。

### 拒絕，而不是提醒

本機限定時，AI 校正與整理的程式**直接拒絕**，不是跳出「確定要送出嗎？」。也**沒有任何旗標可以略過**：提醒可以被順手按掉，旗標可以被複製貼上、或被 AI 代為加上，而機敏內容只要送出一次就收不回來。要解除，只能自己刪標記檔或改設定，程式不提供捷徑，也不替你做。

### 沒有 AI 摘要，改用人工校稿

本機限定不會偷偷改用其他雲端服務或本地模型代替（本地模型目前的品質見第 11 節），所以這一份沒有 AI 摘要。取而代之的是人工：用[會議記錄校稿](/features/proofread)直接校 `transcript.md`、產生定稿逐字稿；校的過程中常錯的詞，勾選後匯入對照表與詞表，**下一次轉寫就更準**。會議記錄校稿認得本機限定：頁首標示「本機限定」，並停用會把內容送出去的「用定稿重做會議記錄」。

### Claude 對話本身也是上雲

在 Claude Code 或 Claude 桌面 App 的對話裡讀逐字稿，就是把逐字稿送到 Anthropic 的雲端。所以 skill 遇到本機限定時，讀逐字稿之前會先提醒、等你明確答應才讀，也不執行 AI 校正與整理的程式；Claude App 裡附上的檔案，在附上的那一刻就已經送出了。機敏內容請不要在 Claude 對話中整理。

怎麼開、會做什麼、被拒絕時的訊息與怎麼解除，見[本機限定（機敏會議）](/features/local-only)。
